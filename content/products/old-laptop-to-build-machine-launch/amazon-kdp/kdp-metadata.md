## Book description (KDP allows ~4,000 characters; HTML light formatting)

> **That old laptop in the drawer could be your first real computer for
> building things.**
>
> You don't need a new machine, a coding background, or any experience with
> Linux to start making websites and small projects. You need the laptop you
> already have and a few free afternoons — and a guide that assumes you know
> nothing yet and explains every step.
>
> *Old Laptop to Build Machine* takes you from "it just sits there" to a working
> development computer with your own website live on the internet. Every term —
> Linux, terminal, Git, repository, deploy — is explained in plain language the
> first time it appears.
>
> **Inside, you'll learn how to:**
> - Tell whether your old laptop is up to the job
> - Back up anything important, safely
> - Install Linux Mint, a friendly and free operating system
> - Set up the tools developers really use: a code editor, Git, Python, Node.js
> - Build a small website by hand
> - Put it online for free and update it whenever you like
> - Decide what to build next
>
> You finish with a laptop running Linux, a website you built yourself, and that
> website live at an address you can share with anyone.
>
> This is an honest, complete walkthrough — not a get-rich scheme, not a
> shortcut to a job, and not a fix for broken hardware. It's the real path from
> an old laptop to a working build machine, written for someone starting from
> zero.
>
> *Companion files — printable checklists, reference cards, and ready-to-run
> setup scripts — are available as a free download; the book explains where to
> get them.*

## Format & production

- **Paperback trim size:** **6 × 9 in** (152 × 229 mm) — the standard,
  economical nonfiction/how-to trim, good for command listings and roomy
  margins. Black-and-white interior on white paper keeps the price low.
- **Page count target:** ~90–120 pages at 6×9 after formatting.
- **Kindle (eBook) considerations:**
  - Reflowable text, not fixed-layout — this is a text guide.
  - Command blocks: use a monospace-styled block; keep lines short (≤ ~60
    chars) so they don't wrap awkwardly on small screens. Prefer breaking a
    long command across documented steps over one very long line.
  - Use real heading styles (H1 chapters, H2 sections) so the Kindle TOC and
    navigation work.
  - Do NOT paste the full setup script as a giant code section — summarize and
    point to the free companion download (see manuscript).
  - Include a linked table of contents.

  (old laptop → arrow → a small live browser window). Imprint "Open Mirror" at
  the bottom. No person, no face.
- **Spine:** title + "Open Mirror."
- **Back:** the short pitch (2–3 sentences), the bullet list of what you'll
  learn, the safety note, and "An Open Mirror playbook · openmirrorllc.com."

  interior), readable and confident.
